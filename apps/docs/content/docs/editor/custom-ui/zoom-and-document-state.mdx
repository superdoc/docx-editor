Zoom and download apply to the document or its view, not the current selection. Put them in your application header,
observe the Editor state that keeps them current, and leave the rest of the built-in toolbar in place.

## Try document-wide controls

1. Use **Zoom out**, **Zoom in**, and **Fit width**. The document and percentage update together.
2. Choose **Download DOCX**. The status reports when the export is ready.

The application owns these document-wide controls. SuperDoc still renders the Editor and the remaining toolbar without
its Zoom control.

## Build zoom and download controls

Start from [Custom UI setup](/editor/custom-ui/controller-setup) with `/sample.docx` in your application's `public`
directory.

The examples below use manual zoom. In `superdoc@2.12.0`, automatic Fit width can shrink the document to 10% after
resizing. The demo above includes a docs-only fitting helper; the copied examples do not depend on it.

### Add the controls

Vanilla adds mounts for the remaining built-in toolbar and the application controls. React creates the built-in toolbar
mount and renders the controls in the component below. For Vanilla, replace the contents of `<body>` in `index.html` with:

`toolbar.excludeItems` removes only Zoom. SuperDoc continues to render the other built-in toolbar controls. Vanilla also
sets `toolbar.container` because the application owns that mount. React creates one when `container` is omitted. Use
`toolbar: false` only when your application will render the complete toolbar.

`ui.zoom` reports the current percentage, mode, and `fitWidth: { min, max }` policy bounds. Those bounds apply only in
Fit width mode. `set()` switches to manual zoom and accepts any finite percentage greater than zero, including 150%
with the default Fit width maximum of 100%. The legacy `min` and `max` fields remain deprecated aliases for the Fit
width bounds. The sample buttons use a 1% minimum for their steps. Zoom changes the view, not the DOCX.

If you construct typed `ZoomSlice` or `SuperDocZoomState` values, add the required `fitWidth` object to your state
literals. Keep the legacy `min` and `max` fields when migrating existing literals; they remain compatibility aliases.

To restore a saved zoom snapshot, call `ui.zoom.set(saved.value)` followed by `ui.zoom.setMode(saved.mode)` when the
saved mode is non-null. Restoring the percentage alone leaves the view in manual mode.

The document snapshot's `ready` field tells you when document actions can run, and its `mode` field reports whether
the Editor is in editing, suggesting, or viewing mode. Read them from `ui.document.getSnapshot()` or receive them from
`ui.document.observe()`, as the examples do, so application controls follow both values without reading the rendered
document DOM.

## React to document changes

`ui.document.onChange()` calls your listener once for each committed change to the current document. Use it to
schedule autosave, keep an activity log, or refresh application state that depends on the content. It is not called
when you subscribe, and it does not wait for the change to be painted. Use `observe()` for state you render.

```ts
const stop = ui.document.onChange((change) => {
  if (change.cause === 'remote') return;
  scheduleAutosave();
  if (change.changeTag) markApplied(change.changeTag);
});
```

Each change reports:

- `cause`: `user` for typing and built-in UI actions, `api` for Document API calls, `undo` and `redo` for history,
  and `remote` for a collaborator's edit.
- `changeTag`: the `changeTag` you passed to the Document API call, or `null`.
- `txId`: the transaction id from the call's receipt, so you can match the change to the call you made.
- `documentEpoch` and `seq`: `seq` counts changes from 1 within one document. Replacing the document starts a new
  `documentEpoch`.
- `scope`: the stories the change touched, or `{ kind: 'unknown' }` when SuperDoc cannot say. Remote changes always
  report an unknown scope; it does not mean nothing changed.

Dry runs, rejected writes, and writes that changed nothing produce no record. Listeners added through
`ui.createScope().document.onChange()` stop when the scope is disposed.

`ui.document.export()` accepts the same typed DOCX options as `superdoc.export()`. It returns `undefined` when the bound
host cannot export. The example passes `triggerDownload: true` so a successful browser export downloads the returned
DOCX.

## Verify the controls

Run the project. The built-in toolbar should render without Zoom. Change the zoom and download the DOCX. The
application status should follow the current percentage and document mode.

Use [Load and save documents](/editor/load-and-save-documents) to send exported bytes to your storage layer. Use
[Document modes](/editor/document-modes) to control editing, suggesting, and viewing.
