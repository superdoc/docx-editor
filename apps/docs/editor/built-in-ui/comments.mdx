Add Word-style commenting to documents with threaded discussions, replies, and resolution workflows.

<Tip>
Building your own comments sidebar in React? Skip this module and read [Custom UI › Comments](/editor/custom-ui/comments) instead. It documents `useSuperDocComments`, `ui.selection.capture()`, and the typed posting flow.
</Tip>

## Quick start

```javascript
const superdoc = new SuperDoc({
  selector: "#editor",
  document: "contract.docx",
  user: {
    name: "John Smith",
    email: "john@company.com",
  },
  modules: {
    comments: {
      allowResolve: true,
      element: "#comments",
    },
  },
  onCommentsUpdate: ({ type, comment }) => {
    console.log("Comment event:", type);
  },
});
```

<Note>
The comments module is **enabled by default**. To disable it entirely, set `modules.comments` to `false`:

```javascript
modules: {
  comments: false;
}
```

</Note>

## Word account identity on export

Configure `user.wordIdentity` with an identity obtained from your account provider. New comments and replies created through `editor.doc.comments.create` or the built-in UI snapshot that pair. Export normally to write the standard Word people association.

```javascript Full Example
import { SuperDoc } from 'superdoc';
import 'superdoc/style.css';

const superdoc = new SuperDoc({
  selector: '#editor',
  document: yourFile,
  user: {
    id: 'app-user-123',
    name: 'Alex Reviewer',
    email: 'synthetic@example.com',
    wordIdentity: {
      providerId: 'AD',
      userId: 'S::synthetic@example.com::opaque-provider-identifier',
    },
  },
  onReady: async ({ superdoc }) => {
    const editor = superdoc.activeEditor;
    if (!editor) return;
    const { items } = editor.doc.query.match({ select: { type: 'text', pattern: 'agreement' } });
    const match = items[0];
    if (match && 'target' in match) {
      const root = editor.doc.comments.create({ target: match.target, text: 'Please review.' });
      if (root.success) {
        editor.doc.comments.create({ parentCommentId: root.id, text: 'Additional context.' });
      }
    }
    await superdoc.export({ isFinalDoc: false, commentsType: 'external' });
  },
});
```

The identifiers above are synthetic. Supply the exact provider pair for your user; SuperDoc does not authenticate the asserted account or derive provider IDs from an application ID, name, or email. Both fields must be non-empty strings containing valid XML characters. New input rejects control characters, including tabs, line breaks, and DEL, so XML attribute normalization cannot change opaque IDs. Accepted strings keep their exact case and spaces. Invalid input throws `TypeError` before creating the comment or producing an export.

Set `wordIdentity: null` to opt out. Without a pair, comments retain their names and private email metadata without a new account association. Replies use the replying user's snapshot. Changing the current user or editing/resolving a comment does not change its original identity. The same `User` configuration works for standalone and headless editors.

Existing Word people entries, unknown providers, and extension data are preserved. When different authors share a display name, Word may show a stable label such as `Alex Reviewer [sd-1a2b3c4d]` to keep their associations separate. A new name/email-only author also receives a separate label when the name is already mapped to an imported account. Labels do not expose the provider ID. Hash collisions receive a numeric suffix. A label remains stable across repeated exports and reopening that artifact; peers with different earlier export histories may have different labels while keeping each comment's exact account association.

For legacy command integrations, `addComment` and `addCommentReply` also accept `authorIdentity: { providerId, userId }` or `null`. An explicit `author`, `authorId`, or `authorEmail` override suppresses the session identity unless `authorIdentity` is also supplied. `editor.doc.comments.create` uses the configured user and takes no per-call author override. Explicit comment records passed to `editor.exportDocx({ comments })` may carry `creatorIdentity` with the same pair shape.

Use a V1 build that includes `wordIdentity` support. Earlier published V1 packages do not acquire this behavior through configuration alone; check your installed release before adopting it. Package associations and visible author labels do not by themselves verify how a recipient's Microsoft directory resolves an account.

## Small-screen behavior

Use `displayMode` to control how comment/tracked-change bubbles render when container width is constrained.

<ParamField path="modules.comments.displayMode" type="'sidebar' | 'inline' | 'auto'" default="'sidebar'">
  Display policy for comment and tracked-change bubbles.
  - `'sidebar'`: always render right sidebar bubbles.
  - `'inline'`: always render compact inline popover mode.
  - `'auto'`: switch between sidebar and inline mode based on measured available width.
</ParamField>

<ParamField path="modules.comments.compactBreakpointPx" type="number">
  Optional fixed compact threshold (px) for `displayMode: 'auto'`.
  If set, inline mode activates when available width is below this value.
</ParamField>

<ParamField path="modules.comments.compactMeasurementSelector" type="string">
  Optional CSS selector for the width measurement target in `displayMode: 'auto'`.
  Useful for custom flex/grid host shells where the default measurement target is not representative.
</ParamField>

```javascript
modules: {
  comments: {
    displayMode: "auto",
  },
}
```

```javascript

  comments: {
    displayMode: "auto",
    compactMeasurementSelector: "#editor-shell",
  },
}
```

## Viewing mode visibility

Comments are hidden by default when `documentMode` is `viewing`. Use
`comments.visible` and `modules.trackChanges.visible` to control what renders
in read-only mode.

```javascript
new SuperDoc({
  selector: "#viewer",
  document: "contract.docx",
  documentMode: "viewing",
  comments: { visible: true }, // Standard comment threads
  modules: {
    trackChanges: { visible: false }, // Tracked-change markup + threads
  },
});
```

<Note>
  The top-level `trackChanges` key still works as a deprecated alias for
  `modules.trackChanges` and will emit a one-time console warning.
</Note>

## Permission resolver

Customize who can resolve comments or accept tracked changes. The resolver receives the permission type, current user, and any tracked-change metadata. Return `false` to block the action.

By default, editors can resolve, edit, and delete any user's comments and tracked changes: regardless of authorship. Use `permissionResolver` to restrict actions when needed.

```javascript
modules: {
  comments: {
    permissionResolver: ({
      permission,
      trackedChange,
      currentUser,
      defaultDecision,
    }) => {
      if (
        permission === "RESOLVE_OTHER" &&
        trackedChange?.attrs?.authorEmail !== currentUser?.email
      ) {
        return false; // Block accepting suggestions from other authors
      }
      return defaultDecision;
    },
  },
}
```

Available permission types:

| Permission | Description |
|---|---|
| `RESOLVE_OWN` | Resolve your own comments |
| `RESOLVE_OTHER` | Resolve other users' comments |
| `REJECT_OWN` | Reject your own tracked changes |
| `REJECT_OTHER` | Reject other users' tracked changes |
| `COMMENTS_OVERFLOW_OWN` | Edit your own comments |
| `COMMENTS_OVERFLOW_OTHER` | Edit other users' comments |
| `COMMENTS_DELETE_OWN` | Delete your own comments |
| `COMMENTS_DELETE_OTHER` | Delete other users' comments |

<Note>
  You can set a global resolver with the top-level `permissionResolver` config.
  Module-level resolvers take precedence when both are defined.
</Note>

## Word import/export

Word comments are automatically imported with the document and marked with `importedId`. When exporting, use the `commentsType` option:

<CodeGroup>

```javascript Usage
// Include comments in export
const blob = await superdoc.export({ commentsType: "external" });

// Remove all comments
const cleanBlob = await superdoc.export({ commentsType: "clean" });
```

```javascript Full Example
import { SuperDoc } from 'superdoc';
import 'superdoc/style.css';

const superdoc = new SuperDoc({
  selector: '#editor',
  document: yourFile,
  user: { name: 'John Smith', email: 'john@company.com' },
  modules: { comments: { allowResolve: true } },
  onReady: async (superdoc) => {
    // Include comments in export
    const blob = await superdoc.export({ commentsType: "external" });

    // Remove all comments

});
```

### `scrollToComment`

Scroll the document to a comment and set it as active. Unlike `setCursorById`, this is a top-level SuperDoc method that works without accessing the editor directly.

<CodeGroup>

```javascript Usage
superdoc.scrollToComment("comment-123");
```

```javascript Full Example
import { SuperDoc } from 'superdoc';
import 'superdoc/style.css';

const superdoc = new SuperDoc({
  selector: '#editor',
  document: yourFile,
  modules: { comments: {} },
  onReady: (superdoc) => {
    const { items } = superdoc.editor.doc.comments.list();
    if (items.length > 0) {
      superdoc.scrollToComment(items[0].id);
    }
  },
});
```

</CodeGroup>

## Events

### `onCommentsUpdate`

Fired for all comment changes.

<ParamField path="type" type="string" required>
  Event type: `pending`, `add`, `update`, `deleted`, `resolved`, `selected`, `change-accepted`, or `change-rejected`
</ParamField>

<ParamField path="comment" type="Comment" required>
  The [Comment](#comment-data-structure) object
</ParamField>

<ParamField path="meta" type="Object">
  Additional metadata
</ParamField>

```javascript
onCommentsUpdate: ({ type, comment, meta }) => {
  switch(type) {
    case 'add':
      await saveComment(comment);
      break;
    case 'resolved':
      await markResolved(comment.id);
      break;
  }
}
```
