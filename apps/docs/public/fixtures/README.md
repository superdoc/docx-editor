# Documentation fixtures

All fixtures are synthetic and contain no customer data. The repository's
DOCX privacy gate rejects unapproved metadata, and `tests/fixtures.test.mjs`
adds the guarantees below.

Sanitization covers human-identifying metadata: author and last-modified-by
fields are emptied, the company and manager fields are cleared, and the
generating application is replaced with `SuperDoc`. It does not strip Word's
machine metadata. `sample-nda.docx` and `tracked-changes.docx` still carry revision session identifiers,
paragraph ids, an `AppVersion`, and the source document's bibliography part.
None of it identifies a person, but do not treat these fixtures as an example
of exhaustive document scrubbing.

## `getting-started.docx`

The Editor Quickstart's one-page statement of work. Its title, headings, real
bulleted list, milestone table, and signature fields make the first edit and
export visible in a familiar business document.

Generated by `scripts/build-getting-started-fixture.mjs` as a minimal,
byte-stable OOXML package. The content is synthetic. The fixture has no
comments, tracked changes, or identifying metadata.

## `sample-nda.docx`

The framework guides' sample document. Deliberately clean: no tracked changes
and no comments. It keeps real Word styles (Heading 1, Heading 2, a bulleted
list) so the first render demonstrates DOCX fidelity rather than plain text.

Generated from `fixtures/nda.docx` (synthetic, redistributable) by
`scripts/build-quickstart-fixture.mjs`, which strips revision and comment markup
and replaces core and extended properties with sanitized values. The build is
byte-stable, so regenerating it produces no git diff.

Regenerate with:

```bash
pnpm --filter @superdoc/docs generate:fixtures
```

## `tracked-changes.docx`

Reserved for the review documentation, where an existing suggestion is the
point. A synthetic NDA derived from the same source with one tracked insertion
(`(as amended)`, inserted after a `termination` clause by author "Reviewer") so
the headless quickstart can query the word `termination` and accept a tracked
change.

## `formatting-sample.docx`

The custom UI overview's live Bold control. Three short paragraphs, no headings,
no tracked changes, no comments: the page asks the reader to select one sentence
and press one button, so anything else is something to scroll past first.

Unlike the other two, this one is authored by its generator rather than derived
from `fixtures/nda.docx`. Trimming a contract down to a prompt leaves contract
residue behind, and a purpose-built document is smaller (about 3 KB against 23 KB)
and says exactly what the page needs it to say.

Generated by `scripts/build-demo-fixtures.mjs`, which writes a minimal OOXML
package with fixed entry dates so the build is byte-stable.
